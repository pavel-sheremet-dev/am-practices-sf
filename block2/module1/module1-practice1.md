## Завдання. Telegram-бот: пост із зображенням і погодженням

**Що будуємо:**

```
Назва_телеграм_ноди (Telegram Trigger)
  → Switch — шукає в тексті ключове слово формату

      ├─ квадрат  → Generate an image (1024×1024)  ┐
      ├─ портрет  → Generate an image (1024×1536)  ├→ Merge (3 входи)
      ├─ альбом   → Generate an image (1536×1024)  ┘
      │
      └─ Fallback → Generate general response → Send instructions

  Merge
    → Create Post             GPT пише підпис до фото
    → Send Post Preview       фото + підпис у чат
    → Send Approval Message   «Опублікувати пост?» + дві кнопки
    → If                      approved = true?
          true  → Send Post   фінальна публікація
          false → виконання завершується
```

**Приклади повідомлень:**

```
квадрат, кава в мінімалізмі
портрет, банер про запуск нової колекції
album, горизонтальний банер про CRM для малого бізнесу
привіт, що ти вмієш?
```

Перші три дають зображення у відповідному форматі, останнє — підказку, як користуватися ботом.

### Крок 2. Telegram Trigger і Switch: визначаємо формат

**Що зробити.**

- Нода **Telegram Trigger**. Updates — `message`.
- Надіслати боту тестове повідомлення, подивитись вихід: `message.text`, `message.chat.id`, `message.from`.
- Нода **Switch**, режим **Rules**, три правила. У кожному — одна умова типу **Boolean**, операція **is true**:

```
квадрат
{{ ["square", "квадрат"].some(item => $('Назва_телеграм_ноди').item.json.message.text.toLowerCase().includes(item)) }}

портрет
{{ ["portrait", "портрет"].some(item => $('Назва_телеграм_ноди').item.json.message.text.toLowerCase().includes(item)) }}

альбом
{{ ["album", "landscape", "альбом"].some(item => $('Назва_телеграм_ноди').item.json.message.text.toLowerCase().includes(item)) }}
```

- Для кожного правила увімкнути **Rename Output** і дати виходу назву: `квадрат`, `портрет`, `альбом`.
- В **Options** додати **Fallback Output → Extra Output**. З'явиться четвертий вихід для повідомлень, у яких формату немає.

**На що звернути увагу:**

- **Розберіть вираз частина за частиною** — у ньому три прийоми одразу:
  - `.toLowerCase()` приводить текст до нижнього регістру, тому `INSTA`, `Insta` та `insta` спрацьовують однаково. У домашньому завданні це пряма вимога;
  - `.includes(item)` шукає слово **будь-де в тексті**, а не тільки на початку. Тому «зроби мені альбом — банер про CRM» спрацює так само, як «альбом, банер про CRM»;
  - `.some(...)` повертає `true`, якщо підійшло **хоч одне** слово зі списку. Так один вихід ловить і «album», і «landscape», і «альбом».

### Крок 3. Генерація зображення: три гілки і Merge

**Що зробити.**

- До кожної гілки підключити ноду **OpenAI**, Resource — **Image**, Operation — **Generate an Image**

Промпт:

```
Згенеруй зображення на основі наступного запиту:

[[текст_запиту]]
```

- В залежності від формату (квадрдат, портрет, альбом), обрати потрібні опції
- Нода **Merge**, **Number of Inputs — 3**, режим **Append**. Завести в неї всі три гілки: square → Input 1, portrait → Input 2, album → Input 3.

**На що звернути увагу:**

- **Три майже однакові ноди — нормально.** Відрізняється лише один параметр, але в n8n немає способу змінити розмір «на ходу» без додаткової ноди. Альтернатива — зберігати розмір у Set перед генерацією і підставляти виразом; тоді ноду треба лише одну. Обидва варіанти робочі, перший простіший для читання схеми.
- **Навіщо Merge, якщо гілка завжди одна.** Спрацьовує рівно одна з трьох, але далі має йти один спільний ланцюжок. Merge у режимі Append просто пропускає далі те, що до нього дійшло. Без нього довелось би тричі копіювати весь хвіст воркфлоу.
- Зображення приходить як **бінарні дані** у полі `data`, а не як посилання. Це знадобиться вже на наступних кроках.

### Крок 4. Підпис до посту

**Що зробити.**

- Після Merge додати ноду **OpenAI**, Resource — **Text**, Operation — **Response Text**. Назвати `Create Post`. Модель — будь-яка текстова з доступних.
- У промпт передати текст запиту користувача і описати, що має вийти:
  - роль — автор постів для Telegram;
  - структура: перший рядок — заголовок-гачок з одним емодзі, порожній рядок, далі 2–4 речення, останній рядок — заклик до дії;
  - мова відповіді — **та сама, що й мова запиту**;
  - без посилань, без згадок про зображення та про сам промпт;
  - на виході — **тільки текст посту**, нічого більше.

### Крок 5. Превью, погодження і публікація

**Що зробити.**

- Нода **Telegram**, операція **Send Photo**. Назвати `Send Post Preview`.
  - **Chat ID:** `{{ $('Назва_телеграм_ноди').item.json.message.chat.id }}`
  - **Binary File** — увімкнути. У полі назви бінарних даних:

```
{{ $('Merge').item.binary.data }}
```

  - **Caption:** `{{ $json.output[0].content[0].text }}`
- Нода **Telegram**, операція **Send and Wait for Response**. Назвати `Send Approval Message`.
  - **Chat ID:** `{{ $json.result.chat.id }}`
  - **Message:** `Опублікувати пост?`
  - **Approval Type:** **Approve and Disapprove** — дві кнопки.
  - В **Options** вимкнути **Append n8n Attribution**.
- Нода **If**: умова `{{ $json.data.approved }}`, тип **Boolean**, **is true**.
- Гілка **true** → ще одна нода **Telegram / Send Photo**, назвати `Send Post`:
  - **Chat ID:** `{{ $('Назва_телеграм_ноди').item.json.message.chat.id }}`
  - **Binary File** — той самий вираз, що в превью;
  - **Caption:** `{{ $('Create Post').item.json.output[0].content[0].text }}`
- Гілку **false** лишаємо порожньою: відхилили — виконання просто завершується.

**На що звернути увагу:**

- **`Send and Wait for Response` — це і є Human-in-the-loop із конспекту.** Нода надсилає повідомлення з кнопками й **зупиняє виконання**, поки людина не натисне одну з них. Усередині це Wait плюс webhook: n8n віддає кнопкам адресу, за якою чекає на відповідь. Виконання в цей момент висить у стані Waiting — так і має бути.
- **Чому пост надсилається двічі.** Перший раз — превью для перевірки, другий — «публікація». У базовому варіанті обидва йдуть у той самий чат, тому виглядає як дубль. Щоб це стало справжньою публікацією, у `Send Post` треба підставити **ID каналу** і додати бота адміністратором каналу.

### Крок 6. Fallback: підказка, як користуватися ботом

**Що зробити.**

- До четвертого виходу Switch підключити ноду **OpenAI**.
- У промпті описати:
  - роль — асистент усередині Telegram-бота, який генерує зображення;
  - які ключові слова формату бот розуміє: `square` / `квадрат`, `portrait` / `портрет`, `album` / `landscape` / `альбом`;
  - що в повідомленні має бути і ключове слово, і опис зображення;
  - приклад правильного повідомлення;
  - **одне завдання:** на будь-яке повідомлення пояснити, як сформулювати запит, без зайвих порад.

**На що звернути увагу:**

- **Модель тут не обов'язкова.** Підказку можна зробити статичним текстом у ноді Telegram — це дешевше, швидше й передбачуваніше. Модель дає одну перевагу: вона відповідає мовою користувача й реагує на зміст повідомлення..

## Додатково. Куди розвивати бота

Обговорюємо на словах, не збираємо. Це напрямки, у яких цей воркфлоу росте до того, за що платять на фрилансі.

**1. Публікація в канал, а не в чат.**

Найменша зміна з найбільшим ефектом. У ноді `Send Post` замінити Chat ID на ID каналу і додати бота адміністратором каналу.

**2. Голосові повідомлення замість тексту.**

Одразу після тригера ставимо Switch, який дивиться, чи є в повідомленні поле `message.voice`. Якщо є — Telegram **Get a File** завантажує аудіо, воно йде в AssemblyAI (`POST /v2/upload` бінарним тілом, далі `POST /v2/transcript`), і за знайомим циклом **Wait → GET → перевірка статусу** повертається текст. Обидві гілки — текстова й голосова — зводяться в Merge, після чого текст лежить в одному полі незалежно від того, звідки прийшов. Єдине, що доведеться переробити: усі місця, які зараз читають `$('Назва_телеграм_ноди').item.json.message.text` — умови Switch і обидва промпти — треба перевести на вихід Merge.

Ланцюжок транскрибації зручно винести в **окремий subworkflow**: він самодостатній і знадобиться в інших проєктах.

**3. Замість ключових слів — модель, що розуміє запит.**

Найцікавіший напрямок. Switch за ключовим словом ламається на всьому, що не вгадали: «зроби горизонтальну картинку гір» не містить слова «альбом». Перед Switch ставимо **AI Agent зі Structured Output Parser**, який повертає строгий JSON:

```json
{
  "intent": "image",
  "image_format": "album",
  "message": "гори на світанку"
}
```

Сам Switch лишається на місці, але читає вже не текст повідомлення, а готові поля. Що це дає:

- формат розпізнається в будь-якій формі й мові — «квадратну», «в альбомном формате», «9:16»;
- з опису **вирізається** згадка формату й звертання до бота, у промпт генерації йде чистий опис;
- з'являється третій намір — `text`, звичайна розмова з ботом;
- модель відрізняє формат від змісту: «портрет бабусі» — це опис, а не вертикальний формат.
